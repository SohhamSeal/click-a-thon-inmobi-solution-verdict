Chapter 4: Windows and Sampling

What time range we look at, what history we compare to, and what we skip.

Simple first

The investigation window

When you run:

verdict investigate --start 2026-07-05 --hours 24 --grain 1h

You are asking: "What happened between July 5 and July 6, measured at hourly buckets?"

ParameterDefault / optionsMeaning
--startrequiredWindow start timestamp
--hours24How long the incident window is

What is the baseline?

For the temporal detector, each segment is compared to its own recent past. Default: 4 prior weeks of history at the same weekday alignment (baseline_weeks: 4).

Example: Investigating Monday July 7 hourly buckets? Baseline might be the same hours on the four previous Mondays (roughly), pooled together. Expected fill rate = total fills in baseline weeks ÷ total requests in baseline weeks. Not the average of four separate Monday rates unless traffic was equal each week.

Trimming one bad week

With only 4 samples, a robust baseline drops the single most extreme week (by rate), then pools the rest. This survives one contaminated Sunday without needing a fancy median of rates.

What gets tested vs skipped

Not every lattice cell gets a hypothesis test. A cell is tested only if it has enough traffic to detect the effect size we care about.

Per metric power floor

There is no single global volume threshold. Fill rate near 79% and CTR near 1% need wildly different sample sizes to detect a 5% relative move at 80% power.

For each cell, Verdict computes the smallest relative drop that cell's traffic could resolve. If even a near total collapse (95% drop) would be undetectable, the cell goes to the coverage ledger with reason below_detection_floor.

required_denominator ≈ φ × [zα√(2p̄(1−p̄)) + zpower√(p₁(1−p₁)+p₂(1−p₂))]² / (p₁−p₂)²

In plain words: given baseline rate p₁, effect size, significance α=0.01, power 80%, and overdispersion φ, how many trials (requests/impressions) do we need? φ > 1 because ad traffic is "burstier" than pure coin flips.

Overdispersion (φ)

Real ad segments are more variable than binomial/Poisson models assume. Verdict estimates φ from baseline residuals using a robust median (not mean, which one bad week can blow up). φ is clamped between 1.0 and 50.0.

Multiple testing and the window of hypotheses

Per metric per bucket, the scan tests roughly:

  • 46 combos × number of distinct segment values per combo
  • Across 10 metrics in a full run
  • Example: 14,683 cells tested in one 24h run on the build corpus

At α=0.01 uncorrected, you'd expect ~147 false positives by chance alone. Benjamini Hochberg FDR correction runs on the temporal family after all metrics are scanned.

Holdout window (localization)

After detection, localization can split the incident window in half and ask: does the effect show up in both halves?

If an effect only appears in one half, it may be a spike, not a sustained incident. Limitation: both halves are still compared to the same baseline, so holdout validates selection more than baseline quality.

Baseline audit

Before trusting segment history, Verdict can run an audit step: does the baseline still describe this population? If not (as in the unseen dimension relabeling), temporal detection on segments is disabled. The platform total (__all__) may still use history; structural detection uses siblings instead.

The coverage ledger is intentionally much larger than the case list. Silence about a segment and proof it was innocent are different claims.
